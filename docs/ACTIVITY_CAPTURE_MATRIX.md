# Phase 23 mutation capture contract

This matrix is the implementation checklist for Activity History. All user rows require one audit event in the **same transaction** as the canonical mutation. Canonical failure and audit failure must roll back both. No-op semantic changes produce no event. Shared writers contribute to their caller's group and never open a second transaction or workspace gate.

## Operation identity

Operation GUIDs identify one invocation, not an indefinitely replayable command. No automatic replay follows an ambiguous commit. Reconciliation reads canonical identities and, while available, the matching audit event. Clear History removes audit deduplication evidence; it does not authorize replay. Restart and Profile switches discard pending UI requests. Explicitly repeating a command is a new user action. Audit records are not a durable command ledger.

## Internal writer restriction

Shared Page/Canvas/Widget/Decoration/content writers are internal transaction participants. Maintenance and recurrence materialization are explicitly excluded. Public canonical mutation entry points must capture transactionally, including direct repository callers. Raw SQL from external programs is outside the application audit contract.

Creation/deletion changes retain existence and identity, not complete scalar snapshots. Definition/field deletion summarizes historical cascades at that definition/field; it does not enumerate every removed entry value. Shared internal content creation is represented in the outer Widget/Page Template group. Ordinary duplication records the new entity; Template instantiation additionally records explicit source provenance. Fault injection covers representative operations at every transaction family, not every Cartesian combination of domain options. Native acceptance complements these tests with the actual History/date controls, navigation, grouping and confirmation behavior.
